## Шаг 3. Запрос списка фильмов

**Файл: `src/pages/HomePage/HomePage.jsx`**

Нужно завести ещё три состояния (помимо `query` из шага 2):

- массив найденных фильмов (изначально пустой или `null`);
- флаг загрузки (изначально `false`);
- текст ошибки (изначально `null` или пустая строка).

Затем — функцию, которая будет вызываться при сабмите формы (её и передадите
в `SearchBar` как обработчик `onSubmit` из шага 2). Функция асинхронная
(`async function`). Логика внутри:

```
1. Обнулить текст ошибки, включить флаг загрузки.
2. try:
     - дождаться fetch по адресу
       https://www.omdbapi.com/?apikey=КЛЮЧ&s=ЗАПРОС
       (ключ — из import.meta.env, запрос — из state query)
     - дождаться .json() у ответа
     - проверить data.Response:
         если "False"  → записать data.Error в состояние ошибки
         если "True"   → записать data.Search в состояние фильмов
   catch (если fetch упал по сети):
     - записать в состояние ошибки свой текст, например
       "Не удалось связаться с сервером"
   finally:
     - выключить флаг загрузки
```

OMDb **всегда** отвечает HTTP-статусом 200, даже если фильм не найден — поэтому `response.ok` тут не поможет, ошибку нужно искать именно в поле `Response` внутри самого JSON.

Это `try / catch / finally` вокруг `await` — конструкция, которая нужна
всегда, когда одна асинхронная операция может либо успешно завершиться, либо
упасть с ошибкой, либо вернуть логическую неудачу (как в случае с OMDb).

## Шаг 6. Переход на страницу фильма (с роутером)

До этого момента в проекте не было ни одной настоящей ссылки — вся навигация
была бы условным рендерингом вручную. Теперь подключим `react-router-dom`:
он берёт на себя хранение текущего адреса и синхронизацию с URL в браузере,
а вам останется только описать, какой компонент какому адресу соответствует.

### Установка

```
npm install react-router-dom
```


### Файл: `src/main.jsx`

Всё приложение нужно обернуть в `<BrowserRouter>` — это компонент, который
подключает роутер к браузерной истории и адресной строке. Без него хуки вроде
`useNavigate` и `useParams` (они понадобятся дальше) просто не будут работать.

```jsx
import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import { BrowserRouter } from "react-router-dom"
import "./styles/global.css"
import App from "./App.jsx"

createRoot(document.getElementById("root")).render(
    <StrictMode>
        <BrowserRouter>
            <App />
        </BrowserRouter>
    </StrictMode>,
)
```

### Файл: `src/App.jsx`

Раньше здесь предполагалось состояние «какой сейчас экран открыт» и условный
рендеринг трёх страниц вручную — это больше не нужно. Вместо этого опишите
маршруты через `<Routes>` и `<Route>`:

```jsx
import { Routes, Route } from "react-router-dom"
import Header from "./components/Header/Header"
import Footer from "./components/Footer/Footer"
import HomePage from "./pages/HomePage/HomePage"
import MovieDetailsPage from "./pages/MovieDetailsPage/MovieDetailsPage"
import AboutPage from "./pages/AboutPage/AboutPage"

function App() {
    return (
        <>
            <Header />
            <Routes>
                <Route path="/" element={<HomePage />} />
                <Route path="/movie/:imdbID" element={<MovieDetailsPage />} />
                <Route path="/about" element={<AboutPage />} />
            </Routes>
            <Footer />
        </>
    )
}

export default App
```

`Header` и `Footer` остаются снаружи `<Routes>`, потому что это общий layout —
он должен быть виден на всех страницах, а меняться должен только контент
внутри `<Routes>`.

Обратите внимание на `path="/movie/:imdbID"` — часть пути с двоеточием
называется **параметром маршрута**: он означает «сюда подставится любое
значение, и я хочу иметь к нему доступ по имени `imdbID`». Как получить это
значение внутри страницы — в шаге про `MovieDetailsPage` ниже.

## 1. Как устроен запрос через fetch

`fetch` — встроенная в браузер функция, которая отправляет HTTP-запрос и
возвращает `Promise`. Работать с `Promise` внутри React-компонента удобнее
всего через `async/await`.

```js
async function loadData() {
  const response = await fetch('https://example.com/api/data');
  const data = await response.json();
  console.log(data);
}
```

Что здесь происходит по шагам:

1. `fetch(url)` отправляет запрос и сразу возвращает `Promise` — он ещё не
   содержит данные, а лишь обещание, что рано или поздно они появятся.
   `await` «останавливает» выполнение функции до момента, пока сервер не
   пришлёт ответ (при этом сам браузер в это время не блокируется, это
   касается только выполнения именно этой функции).
2. Результат `await fetch(...)` — объект `Response`. Это ещё не данные, а
   «конверт» с ответом: заголовки, статус-код и тело, которое нужно отдельно
   распарсить.
3. `response.json()` читает тело ответа и парсит его как JSON — тоже
   асинхронная операция, поэтому снова нужен `await`.

`async` перед объявлением функции обязателен, если внутри неё используется
`await` — без `async` слово `await` использовать нельзя.

### try / catch / finally вокруг запроса

Запрос может завершиться тремя разными способами: успехом, сетевой ошибкой
(нет интернета, сервер недоступен) или логической неудачей на уровне ответа
(например, API вернул `{ "Response": "False" }`, оставаясь при этом
технически «успешным» HTTP-ответом). Первые два случая различают через
`try/catch`, третий — обычной проверкой поля в уже полученных данных:

```js
async function loadData() {
  setError(null);
  setIsLoading(true);

  try {
    const response = await fetch(url);
    const data = await response.json();

    if (data.Response === 'False') {
      setError(data.Error);      // логическая неудача от самого API
    } else {
      setResult(data);
    }
  } catch (err) {
    setError('Проблема с сетью'); // fetch не смог выполниться вообще
  } finally {
    setIsLoading(false);          // выполнится в любом случае
  }
}
```

`catch` сработает, только если сам `fetch` или `response.json()` выбросили
исключение (например, недоступен сервер, оборвалось соединение, ответ —
не валидный JSON). Если сервер ответил, но с «отказом» внутри JSON — это
не ошибка с точки зрения `fetch`, а обычные данные, которые нужно проверять
руками, как в примере выше.

## 2. Шаблонные строки и `${}`

Шаблонные строки (template literals) — строки в обратных кавычках
`` ` `` ``, внутри которых можно подставлять значения переменных через `${}`.
Это удобнее, чем склеивать строки через `+`.

```js
const name = 'Ivan';
const age = 25;

// через конкатенацию
const messageOld = 'Привет, ' + name + '! Тебе ' + age + ' лет.';

// через шаблонную строку
const message = `Привет, ${name}! Тебе ${age} лет.`;
```

### Несколько переменных подряд — например, в URL с query-параметрами

Внутри `${}` можно писать любое JS-выражение, а подставлять можно сколько
угодно значений в одной строке — это особенно полезно при сборке URL с
несколькими параметрами:

```js
const baseUrl = 'https://example.com/api';
const apiKey = 'abc123';
const query = 'batman';
const page = 2;

const url = `${baseUrl}/?apikey=${apiKey}&s=${query}&page=${page}`;
// => "https://example.com/api/?apikey=abc123&s=batman&page=2"
```

Каждый `${...}` — независимая вставка, они не обязаны быть рядом и могут
чередоваться с обычным текстом строки как угодно.

### Экранирование значений в URL

Если значение переменной может содержать пробелы или спецсимволы (например,
поисковый запрос от пользователя), перед подстановкой в URL его стоит
обработать через `encodeURIComponent`, иначе URL может собраться некорректно:

```js
const query = 'blade runner 2049';
const url = `${baseUrl}/?s=${encodeURIComponent(query)}`;
// => ".../?s=blade%20runner%202049"
```

Без `encodeURIComponent` пробел в строке `blade runner 2049` превратился бы
в разрыв URL, а не остался частью значения параметра.

## 3. Переменные окружения в Vite (`.env`)

Хранить ключи API прямо в коде — плохая практика: такой файл легко случайно
закоммитить в публичный репозиторий. Вместо этого секреты выносят в
отдельный файл `.env`, который не должен попадать в git.

### Создание `.env`

Файл создаётся в корне проекта, рядом с `package.json`:

```
VITE_API_KEY=abc123
```

### Чтение переменной в коде

Обращаться к переменным из `.env` нужно через объект `import.meta.env`, а
не через `process.env` (это способ Node.js/Create React App, в Vite он не
работает):

```js
const apiKey = import.meta.env.VITE_API_KEY;

const url = `https://example.com/api/?apikey=${apiKey}`;
```

### Всё вместе: запрос с ключом и параметром

```js
const API_KEY = import.meta.env.VITE_API_KEY;

async function search(query) {
  const url = `https://example.com/api/?apikey=${API_KEY}&s=${encodeURIComponent(query)}`;

  const response = await fetch(url);
  const data = await response.json();

  return data;
}
```

Здесь в одной шаблонной строке сразу два `${}` — ключ из `.env` и
пользовательский запрос, приведённый через `encodeURIComponent` к
безопасному для URL виду.
